# Experimental bgfx world passes

The normal engine renderer remains the default. Configure the full engine with
`STORM_ENABLE_BGFX=ON` to compile the experimental code alongside it. This is not
a complete game backend: only fog and the `Sky`, `SkyBlend`, `SkyBlend_alpha`
material families are ported. Depth-enabled land variants, actors, sea, particles,
render targets and the game UI still need migration. Unknown materials and missing
texture bindings fail explicitly.

Dependencies are pinned by the FetchContent commit and its bgfx/bx/bimg gitlinks
in CMakeLists.txt. A C++20 compiler, CMake 3.21+, Vulkan driver and host development
headers required by upstream bgfx are needed. Never bundle commercial game assets.

## Build and check the passes

```sh
cmake -S src/libs/renderer_bgfx -B build/bgfx-host -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build/bgfx-host -j2
ctest --test-dir build/bgfx-host --output-on-failure
```

The host shader compiler generates SPIR-V from the GPL engine shader sources.
Tests use synthetic textures and generated engine meshes, require Vulkan and do
not use a Noop fallback. `VK_DRIVER_FILES` can select a software Vulkan ICD.

For ARM64 use the engine's Android toolchain and `STORM_ANDROID_NDK`. Building
`storm_bgfx_link_check` checks final linkage; it is never packaged. Cross-builds
consume shaders generated by the host build, not legacy D3D bytecode.

## Resource boundaries

`ColoredMesh` and `TexturedMesh` own buffers and consume bounded CPU data. Legacy
and bgfx implementations receive the same world/material/draw-range descriptors.
The textured batch preserves pass/range order. `TextureStore` owns decoded RGBA8
uploads, retains CPU pixels for color reads and never reuses released IDs. The
store must outlive `SkyPass`; all passes/stores must die before bgfx shutdown.

The bgfx sky shader preserves the original two-texture operation (the second
texture is not multiplied by diffuse) and the cloud mask's reversed alpha blend.
It uses ordered views and clamp addressing. New material/depth variants require
explicit implementation and tests; they must not silently substitute this pass.

## Optional fog capture/replay

A bgfx-enabled engine can capture real SKY fog data on F11 when
`bgfx_fog_capture_file` is set to a writable absolute path in engine.ini. On a
subsequent launch, `bgfx_fog_preview_file` selects that snapshot and
`bgfx_shader_directory` supplies `vs_fog.bin` and `fs_fog.bin`. This path owns a
separate SDL window before game services initialize; DXVK never shares its
surface. Clear the preview key to play. This is fog-only replay, not gameplay.
Resolution/vsync settings apply; `bgfx_preview_fog=0/1` toggles the pass.

`STORM_BGFX_BUILD_SDL_PREVIEW=ON` additionally builds the SDL lifetime check when
SDL2 is available. Run `storm_bgfx_preview_check <shader-output-directory>` on an
X11 display (or under `xvfb-run -a`). No test should use the shared Android device.

## Animated vertex streams

`DynamicVertexStream` owns a complete position/normal/ARGB/UV pose (36-byte
vertices) and exposes an ID valid only for its lifetime and selected renderer.
`SkinningStreamCache` keeps separate CPU staging and GPU streams per source VB;
source-lifetime invalidation releases its dependent buffers before geometry teardown.
Each animated Realize begins a new pose epoch, including stationary or paused
actors: normalized animation position alone cannot identify head/blend/action
changes. A source uploads once within that draw. Staging adds a CPU copy per
animated source buffer; this conservative correctness policy does not establish
a performance improvement. Measure its CPU, GPU and memory costs on real scenes
and devices.

The geometry transform callback now takes an explicit context and returns a
`VertexBufferId`. Rebuild all geometry/model consumers together; old callback
binaries are incompatible. Legacy geometry draws by the actual registered buffer
ID, including the caustic path. The bgfx stream implements upload/binding only:
actor materials, lighting and geometry index-resource dispatch still need porting.
`bgfx_dynamic_stream_pixels` validates the upload layout with a test-only shader;
it is not a completed character-rendering shader.
